KAFKA STUDY 27/35 · OFFICIAL SOURCE 27

Kafka Connect 구조와 가이드

공식문서의 개념을 쉬운 비유와 기술 해설, 실무 장애 상황, 정답을 접어두는 면접 질문으로 공부하는 자료입니다.

1. Source/Sink Connector

아주 쉬운 비유

다른 창고와 물품을 주고받는 전담 배송 체계입니다. Source/Sink Connector을 이해할 때에도 먼저 누가 이 정보를 사용하는지, 어떤 상황에서 필요한지 생각하면 이해하기 쉽습니다.

실제 Kafka 내부에서는?

Source는 외부 시스템에서 Kafka로 읽고 Sink는 Kafka에서 외부로 씁니다. Connector 설정과 Task 실행 상태를 구별합니다.

Source/Sink Connector이 등장하는 요청 흐름에서는 클라이언트 또는 Broker가 필요한 데이터를 전송하고, 수신자가 형식·권한·상태 등을 확인합니다. 요청이 실패했을 때 모든 오류를 똑같이 재시도해서는 안 됩니다. 어떤 상태가 저장되었고 어느 작업을 다시 해야 하는지를 구분해야 합니다.

운영·장애 상황

문제가 발생하면 설정과 버전, 요청을 보낸 주체, Broker 및 클라이언트 로그를 먼저 대조하세요. Source는 외부 시스템에서 Kafka로 읽고 Sink는 Kafka에서 외부로 씁니다. Connector 설정과 Task 실행 상태를 구별합니다. 무작정 서비스 재시작으로 해결하기 전에 원인을 재현하고 변경 후 메트릭을 비교해 보세요.

Q. Source/Sink Connector이 필요한 이유와 원리는? (답변 펼치기)

다른 창고와 물품을 주고받는 전담 배송 체계입니다.

정확한 답변: Source는 외부 시스템에서 Kafka로 읽고 Sink는 Kafka에서 외부로 씁니다. Connector 설정과 Task 실행 상태를 구별합니다.

면접에서는 목적 → 정상 요청 흐름 → 실패했을 때 대처 순서로 답하면 좋습니다.

Q. Source/Sink Connector 장애가 반복되면 어떻게 접근하나요?

재현 가능한 입력과 정확한 오류를 수집하고, 설정·접속·권한·호환성·외부 의존성을 분리해 점검합니다. 데이터 손실 또는 중복 위험이 있으면 변경 전에 복구 가능 범위를 먼저 확인하세요.
