04. Producer 설정을 정말 이해하기

편지를 안전하게 보내는 방법

Apache Kafka 4.3 공식 문서의 학습 순서를 토대로 쉽게 풀어쓴 글입니다. 비유는 이해를 돕기 위한 것으로 실제 시스템 동작과 구분해 읽으세요.

이번 글의 목표

편지를 안전하게 보내는 방법 개념을 설명하고, 내부 흐름·운영 시 주의점·면접 질문까지 연결합니다.

1. 먼저, 아주 쉬운 비유

우체통에 편지를 넣고 바로 돌아갈까요? 아니면 우체부가 받았다고 확인해 줄 때까지 기다릴까요? Kafka Producer의 acks가 바로 이런 확인 수준입니다.

2. 정확한 개념과 용어

acks=0은 확인을 기다리지 않고, acks=1은 Leader의 확인을 받으며, acks=all은 ISR 복제 조건에 따른 확인을 기다립니다. enable.idempotence는 재시도 중 같은 파티션에 중복 기록되는 상황을 줄이는 기능입니다. 애플리케이션 차원의 중복 비즈니스 요청까지 자동 제거하는 것은 아닙니다.

3. 백엔드 실무 예시

linger.ms는 작은 레코드를 잠시 모아 배치 전송할 수 있는 시간입니다. batch.size는 파티션별 배치를 구성하는 용량 기준입니다. compression.type은 압축을 지정합니다. delivery.timeout.ms, request.timeout.ms, retries가 함께 실제 재시도 동작을 결정합니다.

4. 안에서는 어떤 일이 일어날까?

Java 예시: KafkaTemplate<String, String> template; template.send("orders", orderId, payload).whenComplete((result, error) -> { if (error != null) { /* 실패 기록·복구 정책 */ } }); 전송 Future 완료를 확인하고, 종료 직전에 비동기 전송을 방치하지 마세요.

5. 장애가 나면 무엇을 볼까?

Producer가 성공 응답을 주었어도 DB 트랜잭션까지 원자적으로 성공한 것은 아닙니다. 중요한 업무 이벤트는 Outbox, 멱등 Consumer, 재처리 전략을 함께 설계해야 합니다.

6. 면접 꼬리 질문

Q. acks=all이면 절대 유실되지 않나요? A. ISR, 복제 설정, 장애 유형, 운영 조건에 따라 다릅니다. 절대 보장이라고 단정할 수 없습니다.
