Kafka Broker 핵심 설정을 처음부터 깊게 이해하기

설정 이름만 암기하지 말고 왜 필요한지부터 살펴봅니다. 실제 운영에서 문제가 자주 되는 KRaft, 리스너, 로그 저장, 복제 설정에 집중합니다.

1. node.id

어린이도 이해하는 비유

반마다 고유한 반 번호가 있어야 서로를 헷갈리지 않겠지요.

실제 Broker에서 의미하는 것

KRaft에서 노드가 자신을 식별할 때 사용하는 정수형 ID입니다. Broker 또는 Controller 역할 노드에서 고유해야 합니다. 단순히 IP 주소가 같으면 같은 노드라는 뜻이 아닙니다.

설정 예시 — 환경에 맞게 변경

node.id=1

장애가 나면?

서로 다른 서버에 node.id를 중복 지정하면 메타데이터와 노드 식별에 문제가 생길 수 있습니다. 노드 식별과 실제 저장 디렉터리의 포맷 정보가 일치하는지 확인해야 합니다.

2. process.roles

어린이도 이해하는 비유

학교에 선생님도 있고 교감 선생님도 있어요. 한 사람이 두 역할을 맡을 수도 있지만 일이 커지면 분리하는 편이 낫겠죠.

실제 Broker에서 의미하는 것

KRaft 노드가 broker, controller 또는 broker,controller 역할을 맡는지 정합니다. Broker는 데이터를 저장하고 요청을 처리하며 Controller는 클러스터 메타데이터 합의를 수행합니다. 개발용 combined 모드와 운영 분리 구성을 구별해야 합니다.

설정 예시 — 환경에 맞게 변경

process.roles=broker

장애가 나면?

역할 변경은 리스너와 쿼럼 구성까지 영향을 주므로 운영 중 단순 문자열 변경으로 끝내지 마세요.

3. controller.quorum.bootstrap.servers

어린이도 이해하는 비유

학교 대표를 찾기 위해 처음 연락할 연락망입니다.

실제 Broker에서 의미하는 것

KRaft 동적 쿼럼 환경에서 컨트롤러 쿼럼을 찾기 위한 초기 주소 목록입니다. 클라이언트의 bootstrap.servers와 목적이 다릅니다. 4.3 공식 Broker 설정에서 중요 항목으로 제시됩니다.

설정 예시 — 환경에 맞게 변경

controller.quorum.bootstrap.servers=controller1:9093,controller2:9093,controller3:9093

장애가 나면?

Controller 주소는 외부 Producer용 Broker 주소가 아니며 컨트롤러 리스너와 네트워크 접근성을 분리해 점검해야 합니다.

4. controller.listener.names

어린이도 이해하는 비유

관리실 전화와 학생 교실 전화가 구분됩니다.

실제 Broker에서 의미하는 것

컨트롤러 통신에 사용하는 Listener의 이름 목록입니다. Broker가 컨트롤러 쿼럼과 소통할 때 어떤 리스너를 사용해야 하는지 알려줍니다.

설정 예시 — 환경에 맞게 변경

controller.listener.names=CONTROLLER

장애가 나면?

리스너 이름만 지정하고 해당 Listener 정의나 Security Protocol 매핑이 틀리면 연결이 실패할 수 있습니다.

5. listeners와 advertised.listeners

어린이도 이해하는 비유

건물의 실제 출입문과 외부 손님에게 안내하는 주소는 다릅니다.

실제 Broker에서 의미하는 것

listeners는 Broker가 연결을 받도록 바인딩할 주소, advertised.listeners는 클라이언트에게 자신에게 접근할 주소로 알리는 메타데이터입니다. 클라이언트는 bootstrap 후 advertised 주소를 이용하여 파티션 리더로 연결할 수 있습니다.

설정 예시 — 환경에 맞게 변경

listeners=PLAINTEXT://0.0.0.0:9092
advertised.listeners=PLAINTEXT://broker.example.internal:9092

장애가 나면?

Docker나 Kubernetes 환경에서 advertised.listeners에 외부에서 접근할 수 없는 localhost를 넣으면 최초 연결이 되어도 Produce 또는 Fetch가 실패할 수 있습니다.

6. log.dirs

어린이도 이해하는 비유

물품을 어느 창고에 보관할지 정해야 합니다.

실제 Broker에서 의미하는 것

브로커의 로그 데이터가 기록될 디렉터리 목록입니다. 데이터 파티션의 세그먼트·인덱스 등 파일 배치와 관계되며 디스크 용량·지연·가용성이 중요합니다.

설정 예시 — 환경에 맞게 변경

log.dirs=/var/lib/kafka/data

장애가 나면?

저장 장치를 가득 채우면 새 레코드 쓰기와 복제가 실패할 수 있습니다. 디스크 공간·IO 대기·운영 파일 권한을 함께 확인하세요.

7. num.network.threads와 num.io.threads

어린이도 이해하는 비유

학교 안내 데스크 직원과 서류를 처리하는 직원은 다른 일을 합니다.

실제 Broker에서 의미하는 것

브로커는 네트워크 연결·요청과 로그 작업 등 다양한 활동을 처리합니다. 네트워크 처리 스레드와 요청 처리 스레드의 설정은 처리량·지연에 영향을 줄 수 있으나 숫자를 무조건 늘리는 것이 성능 개선을 보장하지 않습니다.

설정 예시 — 환경에 맞게 변경

num.network.threads=3
num.io.threads=8

8. min.insync.replicas

어린이도 이해하는 비유

서류 사본이 최소 몇 곳에 준비되어 있어야 발행 완료라고 인정할지 정하는 규칙입니다.

실제 Broker에서 의미하는 것

Producer가 acks=all로 쓰는 경우 필요한 최소 ISR 수와 관련되는 Topic/Broker 정책입니다. RF 자체와 다른 설정이며 파티션의 ISR이 부족하면 쓰기를 거부할 수 있습니다.

설정 예시 — 환경에 맞게 변경

min.insync.replicas=2

장애가 나면?

RF=3,minISR=2에서 정상 ISR이 한 개만 남은 상황을 실습으로 생각해 보세요. 무손실 보장과 쓰기 가용성의 교환관계가 있습니다.

어린이도 이해하는 비유

오래된 공지와 보관함을 언제 정리할지 정합니다.

브로커 기본 보존 정책과 로그 세그먼트 크기를 결정하는 설정들입니다. Topic별 설정으로 재정의될 수 있어 실제 적용값을 확인해야 합니다. 삭제 기준을 지난 레코드가 즉시 개별적으로 지워지는 것은 아닙니다.

면접 Q&A — 정답 펼치기

Q1. KRaft Broker와 Controller는 같은 프로세스인가요?

process.roles에 따라 분리할 수도 함께 실행할 수도 있습니다. 역할과 운영 장애 도메인을 별도로 설계해야 합니다.

Q2. node.id와 Broker 주소는 같은 뜻인가요?

아닙니다. node.id는 논리적인 고유 식별자이고 주소는 통신 경로입니다.

Q3. bootstrap.servers에 접속되는데 Producer가 실패합니다. 왜죠?

메타데이터를 받은 뒤 advertised.listeners에 포함된 파티션 리더 주소로 연결하지 못할 수 있습니다. 네트워크 접근성을 확인하세요.

Q4. controller.listener.names가 중요한 이유는?

KRaft 컨트롤러 통신에 사용할 Listener를 식별하기 때문입니다. 설정 누락이나 Security Protocol 불일치는 연결 장애를 만들 수 있습니다.

Q5. log.dirs가 가득 차면?

로그 쓰기·복제 및 파티션 가용성에 문제가 생길 수 있습니다. 디스크 잔여 용량·IO 지표를 점검하세요.

Q6. Kafka의 모든 설정은 재시작 없이 변경 가능한가요?

아닙니다. 4.3 Broker 설정마다 UPDATE MODE가 존재하며 read-only 설정은 재시작 등이 필요할 수 있습니다.

Q7. RF=3과 min.insync.replicas=2는 같은 설정인가요?

아닙니다. RF는 복제본 수, minISR은 acks=all 성공에 필요한 동기 복제본 최소 수와 관련됩니다.

Q8. Broker 스레드만 늘리면 빠른가요?

아닙니다. 네트워크·스토리지·압축·CPU·클라이언트 처리 지연 등 실제 병목을 측정해야 합니다.

직접 점검하는 방법

각 설정이 현재 브로커에서 실제로 어떤 값으로 적용됐는지, 동적으로 변경 가능한지 확인하세요. 공식 Broker 설정 레퍼런스의 TYPE·DEFAULT·IMPORTANCE·UPDATE MODE를 같이 읽어야 운영 중 사고를 줄일 수 있습니다.
