프로토콜 버전과 호환성 해석

한 번에 외우려 하지 말고 비유와 실제 기술의 차이부터 읽어 보세요. 각 절은 동작 원리, 정상 처리, 장애 위험을 함께 설명합니다.

1. API Version

5살도 이해하는 이야기

수신자가 이해하는 편지 양식 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

브로커와 클라이언트가 해당 API의 공통 지원 버전을 사용해야 요청·응답을 처리할 수 있다.

실무 포인트: 최신 클라이언트와 이전 브로커 혼합 환경을 테스트한다.

2. Flexible Versions

5살도 이해하는 이야기

확장 가능한 양식 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

태그 필드 같은 메커니즘은 버전 진화와 확장성을 돕는다.

바이너리 파서 구현 시 길이 표현·필드 형식·요청 버전을 정확히 따라야 한다.

언제 문제가 될까?

개발자가 자체 Kafka Wire Client를 제작할 필요는 보통 없다.

🎯 확인 질문: Flexible Versions의 동작과 장애 위험은?

정답: 태그 필드 같은 메커니즘은 버전 진화와 확장성을 돕는다. 바이너리 파서 구현 시 길이 표현·필드 형식·요청 버전을 정확히 따라야 한다.

실무 포인트: 개발자가 자체 Kafka Wire Client를 제작할 필요는 보통 없다.

3. Error Codes

5살도 이해하는 이야기

원인별 다른 실패 신호 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

Not Leader, Authorization, Timeout 같은 성격이 서로 다른 문제는 처리 전략이 다르다.

재시도 전에 클러스터 리더 정보 및 권한을 갱신해야 하는 경우가 있다.

언제 문제가 될까?

로그에서 API Key, Version, Error Code를 함께 확인한다.

🎯 확인 질문: Error Codes의 동작과 장애 위험은?

정답: Not Leader, Authorization, Timeout 같은 성격이 서로 다른 문제는 처리 전략이 다르다. 재시도 전에 클러스터 리더 정보 및 권한을 갱신해야 하는 경우가 있다.

실무 포인트: 로그에서 API Key, Version, Error Code를 함께 확인한다.

4. 호환성 회귀 테스트

5살도 이해하는 이야기

전 학년이 새 교재로 바꿔도 수업을 해야 함 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

Broker 업그레이드 전에 운영 중인 주요 Kafka Clients 조합을 검증한다.

직렬화 형식과 보안 프로토콜은 Kafka Wire 호환성과 별개로 검증해야 한다.

언제 문제가 될까?

Producer, Consumer, Admin을 모두 기능별로 점검한다.

🎯 확인 질문: 호환성 회귀 테스트의 동작과 장애 위험은?

정답: Broker 업그레이드 전에 운영 중인 주요 Kafka Clients 조합을 검증한다. 직렬화 형식과 보안 프로토콜은 Kafka Wire 호환성과 별개로 검증해야 한다.

실무 포인트: Producer, Consumer, Admin을 모두 기능별로 점검한다.
