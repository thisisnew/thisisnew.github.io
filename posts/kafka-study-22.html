22. Kafka 프로토콜 레퍼런스 D

새 기능이 추가돼도 대화가 이어지려면

공부 방법

비유 → 정확한 개념 → 내부 동작과 실제 사용 → 운영·장애 상황 순서로 읽어 보세요. 이해가 어려운 용어는 앞선 강의에서 다시 확인하면 좋습니다.

1. 다섯 살도 이해하는 비유

학교 규칙이 바뀌어도 예전 공지까지 모두 못 읽게 되면 곤란해요. 프로토콜 버전 관리는 이런 문제를 줄이기 위한 장치입니다.

2. 기초부터 정확하게 이해하기

동일한 API라도 버전이 달라지면 필드가 추가되거나 동작 범위가 달라집니다. 최신 브로커가 오래된 클라이언트를 지원하는 범위와 새 클라이언트가 오래된 브로커를 상대하는 범위는 별도로 확인해야 합니다.

3. 실제 시스템에서는?

새로운 기능과 오류 코드는 업그레이드 시 호환성 문제로 이어질 수 있습니다. 클라이언트 의존성만 변경해도 전송·커밋·메타데이터 요청이 받는 영향이 달라질 수 있습니다.

4. 운영과 장애에서 기억할 점

프로토콜 문서를 외울 필요는 없지만 장애 로그에 나온 API Key, version, error code를 공식 레퍼런스와 연결하는 능력은 유용합니다.
