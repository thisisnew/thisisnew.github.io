Streams 운영·보안·리밸런스

도트 게임 속 스테이지를 진행하듯, 쉬운 비유부터 기술적인 흐름과 장애 대응을 함께 익혀봅시다. 비유의 한계를 기억하고 실제 용어를 직접 설명해 보세요.

1. Task Rebalance

처음 듣는 사람을 위한 비유

공장 직원이 교대하며 장부를 넘겨주기

정확한 개념과 내부 동작

Streams Task 재할당은 상태 저장소 이동·복구와 처리 지연을 유발할 수 있다.

실무에서 생기는 문제

배포 중 상태 복원 지표와 lag 변화를 관찰한다.

🎯 연습 문제: Task Rebalance을(를) 설명해 보세요.

정답: Streams Task 재할당은 상태 저장소 이동·복구와 처리 지연을 유발할 수 있다. 배포 중 상태 복원 지표와 lag 변화를 관찰한다.

2. 내부 토픽 권한

처음 듣는 사람을 위한 비유

작업 장부를 쓸 수 있는 열쇠

정확한 개념과 내부 동작

Stateful Topology는 내부 Changelog/Repartition 토픽에 대한 생성·읽기·쓰기 권한이 필요할 수 있다.

실무에서 생기는 문제

최소 권한을 유지하면서 초기 토폴로지 기동을 검증한다.

🎯 연습 문제: 내부 토픽 권한을(를) 설명해 보세요.

정답: Stateful Topology는 내부 Changelog/Repartition 토픽에 대한 생성·읽기·쓰기 권한이 필요할 수 있다. 최소 권한을 유지하면서 초기 토폴로지 기동을 검증한다.

3. 보안 연결

처음 듣는 사람을 위한 비유

공장끼리 비밀 통로 사용

정확한 개념과 내부 동작

Kafka Streams 역시 Kafka Client이므로 TLS/SASL/ACL 설정이 중요하다.

실무에서 생기는 문제

인증서와 JAAS 설정, 특정 토픽 ACL을 분리해 확인한다.

🎯 연습 문제: 보안 연결을(를) 설명해 보세요.

정답: Kafka Streams 역시 Kafka Client이므로 TLS/SASL/ACL 설정이 중요하다. 인증서와 JAAS 설정, 특정 토픽 ACL을 분리해 확인한다.

4. 복구 시나리오

처음 듣는 사람을 위한 비유

정전 뒤 어제 작업부터 이어가기

정확한 개념과 내부 동작

Streams Exactly-once와 State Store 복구는 서로 연결되지만 외부 DB의 원자 갱신을 대체하지 않는다.

실무에서 생기는 문제

재시작, Broker 장애, 상태 파일 삭제를 별도 테스트한다.

🎯 연습 문제: 복구 시나리오을(를) 설명해 보세요.

정답: Streams Exactly-once와 State Store 복구는 서로 연결되지만 외부 DB의 원자 갱신을 대체하지 않는다. 재시작, Broker 장애, 상태 파일 삭제를 별도 테스트한다.

실습과 점검

테스트 토픽과 격리된 Kafka 클러스터에서 각각의 이벤트 Key, Partition, Offset, 처리 성공 여부를 기록하며 결과를 추적하세요. 상태를 사용하는 기능은 앱 재시작 시 복구 시간도 측정합니다. 운영 클러스터의 오프셋을 임의로 수정하거나 Topic을 삭제해서는 안 됩니다.
