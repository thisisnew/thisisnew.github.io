Streams 아키텍처: KStream·KTable

도트 게임 속 스테이지를 진행하듯, 쉬운 비유부터 기술적인 흐름과 장애 대응을 함께 익혀봅시다. 비유의 한계를 기억하고 실제 용어를 직접 설명해 보세요.

1. KStream

처음 듣는 사람을 위한 비유

매분 들어오는 새 주문표

정확한 개념과 내부 동작

KStream은 이벤트가 흘러오는 기록의 스트림으로, 동일 Key에 여러 레코드가 도착해도 개별 이벤트로 처리한다.

실무에서 생기는 문제

주문 완료 이벤트를 실시간 필터링·변환할 때 적합하다.

🎯 연습 문제: KStream을(를) 설명해 보세요.

정답: KStream은 이벤트가 흘러오는 기록의 스트림으로, 동일 Key에 여러 레코드가 도착해도 개별 이벤트로 처리한다. 주문 완료 이벤트를 실시간 필터링·변환할 때 적합하다.

2. KTable

처음 듣는 사람을 위한 비유

주문번호별 현재 상태표

정확한 개념과 내부 동작

KTable은 Key별 상태 변경을 표현하는 추상화로 동일 Key의 새 값이 현재 상태를 갱신하는 의미를 갖는다.

실무에서 생기는 문제

이력 감사 로그와 현재 상태 뷰를 구별한다.

🎯 연습 문제: KTable을(를) 설명해 보세요.

정답: KTable은 Key별 상태 변경을 표현하는 추상화로 동일 Key의 새 값이 현재 상태를 갱신하는 의미를 갖는다. 이력 감사 로그와 현재 상태 뷰를 구별한다.

3. State Store

처음 듣는 사람을 위한 비유

집계한 숫자를 적는 지역 장부

정확한 개념과 내부 동작

Stateful 집계는 로컬 State Store를 사용하고 복구에 Changelog 토픽이 활용될 수 있다.

실무에서 생기는 문제

인스턴스 이동 후 상태 재구축 시간과 디스크 사용량을 고려한다.

🎯 연습 문제: State Store을(를) 설명해 보세요.

정답: Stateful 집계는 로컬 State Store를 사용하고 복구에 Changelog 토픽이 활용될 수 있다. 인스턴스 이동 후 상태 재구축 시간과 디스크 사용량을 고려한다.

4. Task와 Partition

처음 듣는 사람을 위한 비유

컨베이어 하나마다 작업 담당

정확한 개념과 내부 동작

Streams Task는 입력 Partition 할당을 바탕으로 병렬 처리하며 인스턴스 수 변화 시 재할당될 수 있다.

실무에서 생기는 문제

Task 수보다 스레드 수를 늘려도 무조건 빨라지지 않는다.

🎯 연습 문제: Task와 Partition을(를) 설명해 보세요.

정답: Streams Task는 입력 Partition 할당을 바탕으로 병렬 처리하며 인스턴스 수 변화 시 재할당될 수 있다. Task 수보다 스레드 수를 늘려도 무조건 빨라지지 않는다.

실습과 점검

테스트 토픽과 격리된 Kafka 클러스터에서 각각의 이벤트 Key, Partition, Offset, 처리 성공 여부를 기록하며 결과를 추적하세요. 상태를 사용하는 기능은 앱 재시작 시 복구 시간도 측정합니다. 운영 클러스터의 오프셋을 임의로 수정하거나 Topic을 삭제해서는 안 됩니다.
