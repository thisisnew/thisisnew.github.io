1. Produce Request

2. Fetch Request

5살도 이해하는 이야기

책 몇 페이지부터 읽을지 요청 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

Fetch는 특정 파티션의 읽기 위치와 요청 조건에 따라 로그 데이터를 반환한다.

일반 Kafka Consumer가 poll한다고 해서 매번 단일 Fetch 요청 하나만 보내는 것은 아니다.

언제 문제가 될까?

브로커 읽기 가시성, 레코드 가용성 및 max wait를 고려한다.

🎯 확인 질문: Fetch Request의 동작과 장애 위험은?

정답: Fetch는 특정 파티션의 읽기 위치와 요청 조건에 따라 로그 데이터를 반환한다. 일반 Kafka Consumer가 poll한다고 해서 매번 단일 Fetch 요청 하나만 보내는 것은 아니다.

실무 포인트: 브로커 읽기 가시성, 레코드 가용성 및 max wait를 고려한다.

3. Metadata Request

5살도 이해하는 이야기

서랍 담당자를 찾기 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

클라이언트는 토픽의 파티션 리더와 Broker 주소 정보를 받아 적절한 노드로 요청한다.

리더 이동 후 클라이언트는 메타데이터를 갱신할 수 있다.

언제 문제가 될까?

advertised.listeners가 접근 불가하면 부트스트랩 성공 뒤에도 실패한다.

🎯 확인 질문: Metadata Request의 동작과 장애 위험은?

정답: 클라이언트는 토픽의 파티션 리더와 Broker 주소 정보를 받아 적절한 노드로 요청한다. 리더 이동 후 클라이언트는 메타데이터를 갱신할 수 있다.

실무 포인트: advertised.listeners가 접근 불가하면 부트스트랩 성공 뒤에도 실패한다.

4. 프로토콜 버전별 필드

5살도 이해하는 이야기

서식이 바뀌면 칸이 늘어남 이 비유를 실제 기술로 연결해 보겠습니다.

정확한 내부 동작

같은 API Key라도 버전에 따라 필드·유형·태그 필드 여부가 달라질 수 있다.

고수준 kafka-clients API는 이런 구조를 감싸 제공한다.

언제 문제가 될까?

정확한 바이트 형식은 특정 버전의 공식 스키마를 기준으로 판단한다.

🎯 확인 질문: 프로토콜 버전별 필드의 동작과 장애 위험은?

정답: 같은 API Key라도 버전에 따라 필드·유형·태그 필드 여부가 달라질 수 있다. 고수준 kafka-clients API는 이런 구조를 감싸 제공한다.

실무 포인트: 정확한 바이트 형식은 특정 버전의 공식 스키마를 기준으로 판단한다.
