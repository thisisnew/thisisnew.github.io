Kafka Streams 앱 작성과 설정

도트 게임 속 스테이지를 진행하듯, 쉬운 비유부터 기술적인 흐름과 장애 대응을 함께 익혀봅시다. 비유의 한계를 기억하고 실제 용어를 직접 설명해 보세요.

1. StreamsBuilder

처음 듣는 사람을 위한 비유

정확한 개념과 내부 동작

2. application.id

처음 듣는 사람을 위한 비유

공장의 고유한 이름

정확한 개념과 내부 동작

application.id는 처리 그룹과 내부 토픽 자원 등 애플리케이션 상태를 구분하는 핵심 설정이다.

실무에서 생기는 문제

🎯 연습 문제: application.id을(를) 설명해 보세요.

정답: application.id는 처리 그룹과 내부 토픽 자원 등 애플리케이션 상태를 구분하는 핵심 설정이다. 독립 실행해야 할 앱끼리 같은 ID를 실수로 공유하지 않는다.

3. KafkaStreams.start/close

처음 듣는 사람을 위한 비유

공장 가동과 안전한 정지

정확한 개념과 내부 동작

build()로 만든 Topology와 Props로 KafkaStreams를 생성하고 start(), close()를 호출한다.

실무에서 생기는 문제

종료 훅으로 Task 중단과 상태 정리를 고려한다.

🎯 연습 문제: KafkaStreams.start/close을(를) 설명해 보세요.

정답: build()로 만든 Topology와 Props로 KafkaStreams를 생성하고 start(), close()를 호출한다. 종료 훅으로 Task 중단과 상태 정리를 고려한다.

4. 직렬화 설정

처음 듣는 사람을 위한 비유

재료의 포장지를 읽는 규칙

정확한 개념과 내부 동작

default.key.serde와 default.value.serde는 데이터 타입을 해석할 기본 방식을 제공한다.

실무에서 생기는 문제

String으로 보낸 값을 JSON Serde로 읽으면 역직렬화에 실패할 수 있다.

🎯 연습 문제: 직렬화 설정을(를) 설명해 보세요.

정답: default.key.serde와 default.value.serde는 데이터 타입을 해석할 기본 방식을 제공한다. String으로 보낸 값을 JSON Serde로 읽으면 역직렬화에 실패할 수 있다.

실습과 점검

테스트 토픽과 격리된 Kafka 클러스터에서 각각의 이벤트 Key, Partition, Offset, 처리 성공 여부를 기록하며 결과를 추적하세요. 상태를 사용하는 기능은 앱 재시작 시 복구 시간도 측정합니다. 운영 클러스터의 오프셋을 임의로 수정하거나 Topic을 삭제해서는 안 됩니다.
