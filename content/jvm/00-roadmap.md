## 1. 이 연재는 무엇을 설명하는가

Java 코드를 작성해도 실제 CPU가 소스 파일을 직접 읽지는 않습니다. 컴파일 결과를 읽고, 필요한 클래스를 준비하고, 메모리를 관리하고, 스레드를 실행하는 계층이 필요합니다. 이 연재는 그 계층인 JVM을 처음부터 설명합니다. 목표는 용어를 외우는 것이 아니라 “이 Java 코드가 어떻게 실행되고, 왜 이 장애가 나는가?”를 연결하는 것입니다.

첨부한 `JVM_학습순서_01-16.zip`에는 학습 안내와 16개의 주제별 PDF가 있습니다. PDF의 원문 전체를 번역해 옮기는 대신, 학습 목표와 원문 범위를 대응시킨 독립적인 한국어 해설을 작성했습니다. 인접 페이지에 포함된 다른 절은 관련 편에서 다루며, GC처럼 원문이 상세 설명을 제공하지 않는 범위는 공식 가이드로 보충했습니다.

## 2. 사양과 구현, 그리고 버전

**사양**은 여러 JVM이 지켜야 할 약속입니다. 예를 들어 메서드 프레임에 지역변수 배열과 피연산자 스택이 있다는 설명은 JVMS에서 확인합니다. **구현**은 그 약속을 실제로 수행하는 방법입니다. G1의 Region, HotSpot의 C2, Metaspace와 TLAB은 구체적 구현의 이야기입니다. 둘을 섞으면 “모든 JVM은 G1을 쓴다”와 같은 잘못된 결론이 나옵니다.

첨부 자료는 JVMS 23과 JDK 17 JVM Guide 발췌를 섞어 사용합니다. 이 연재의 실행·설명 기준은 **Java SE 21 / HotSpot JDK 21**입니다. 23에서 추가된 기능을 21 기능으로 소개하지 않습니다. Java 21의 class major version은 65이며 23은 67입니다. 가상 스레드 설명도 JDK 21의 pinning 조건을 기준으로 합니다. 패치 버전과 JVM 배포판에 따른 진단 명령 차이는 실행 중인 JVM의 `help`로 확인합니다.

10~13에서는 객체를 만드는 비용과 남겨 두는 비용을 구분합니다. 14~15는 JVM이 같은 의미를 유지하면서 실행을 바꾸는 이유와 안전 조건을 다룹니다. 마지막 16에서는 앞에서 배운 개념으로 관측 자료를 선택합니다. 모든 편의 면접 질문은 먼저 소리 내어 답한 뒤 펼쳐 보세요. 정답 문장보다 반례와 근거를 설명할 수 있는지가 중요합니다.

## 5. 실습 준비와 재현

macOS에서는 설치한 JDK의 경로를 확인하고 Java 21을 선택합니다. JDK 설치 자체는 사용하는 배포판의 공식 절차를 따르세요. macOS ARM64에는 ARM64 JDK가 맞습니다.

```sh
/usr/libexec/java_home -V
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"
java -version
javac -version
```

각 편의 완전한 Java 코드는 저장소의 `examples/jvm/01`부터 `16`에 있습니다. 예를 들어 저장소 루트에서 다음과 같이 실행합니다. `--release 21`은 언어·표준 API·클래스 파일 타깃을 함께 지정합니다. JDK 17에서는 21 타깃을 만들 수 없으므로 JDK 21 이상이 필요합니다.

```sh
cd examples/jvm/01
javac --release 21 -g Lesson01.java
java Lesson01
javap -c -v Lesson01
```

GC·JIT 로그는 하드웨어, JVM 패치, 부하와 타이밍에 따라 달라집니다. 글에 예시라고 표시한 로그를 반드시 그대로 얻어야 성공인 것은 아닙니다. 논리적 출력은 같아야 하지만, GC 횟수·주소·상수 풀 인덱스·시간은 관측값입니다. OOM과 무한 재귀 같은 장애 유발 변형은 격리한 로컬 환경에서만 수행합니다.

## 6. 공식 자료를 읽는 길

처음부터 사양 전체를 정독하기보다 각 글 말미의 절 링크로 이동하세요. 먼저 글의 예제를 이해하고 공식 문서에서 보장 범위를 확인하는 방식이 좋습니다. GC와 JIT는 JVMS가 세부 알고리즘을 강제하지 않으므로 HotSpot 가이드를 함께 읽습니다.

- [JVMS 21 목차](https://docs.oracle.com/javase/specs/jvms/se21/html/index.html): 데이터 영역, 프레임, ClassFile, 로딩·링킹의 규칙.
- [JLS 21](https://docs.oracle.com/javase/specs/jls/se21/html/index.html): Java 언어의 초기화, 참조, 동기화 의미.
- [JDK 21 GC Tuning Guide](https://docs.oracle.com/en/java/javase/21/gctuning/index.html): 세대·수집기·G1·튜닝.
- [JDK 21 JVM Guide](https://docs.oracle.com/en/java/javase/21/vm/index.html): HotSpot 최적화와 NMT.
- [JDK 21 도구 명세](https://docs.oracle.com/en/java/javase/21/docs/specs/man/index.html): javac, javap, java, jcmd, jfr.

## 7. 학습 완료 기준

“GC는 안 쓰는 객체를 지운다”에서 멈추지 않고, “사용 여부를 직접 읽는 것이 아니라 참조 그래프와 도달 가능성으로 판단하므로 static Map이 남긴 참조는 회수되지 않는다”고 설명할 수 있어야 합니다. 같은 방식으로 “JIT는 빠르다”에서 워밍업·인라이닝·추측 실패·역최적화까지 연결해 보세요.

최종 과제는 입고 요청 API가 느려졌다는 상황입니다. CPU는 낮은데 응답이 느리면 락·DB·외부 대기를, CPU와 할당률이 함께 높으면 객체 생성과 GC를, Heap은 안정적인데 RSS가 커지면 Native 영역을 조사한다고 설명해 보세요. 각 결론에 어떤 자료가 필요한지까지 말할 수 있으면 이 연재가 실무 지식으로 연결된 것입니다.

## 8. 더 자세해진 본문을 공부하는 순서

16편 모두에 용어 표, 실행 과정을 천천히 따라가는 설명, 해설이 있는 확인 문제를 추가했습니다. 면접 답변은 먼저 핵심 결론을 읽고, 구체적인 예와 꼬리질문까지 이어서 확인할 수 있습니다. 단어를 외우기보다 같은 개념을 코드·표·장애 상황에 각각 적용하는 것이 목표입니다.

첫 번째로 읽을 때에는 용어 표와 기본 Java 예제에 집중하세요. 두 번째로 읽을 때에는 ‘차근차근 이해하기’의 상태 변화와 조건을 바꾸는 실습을 따라갑니다. 마지막에는 답변을 접어 둔 채 질문에 직접 답하고, 펼친 해설과 비교합니다. 예측이 틀렸다면 결론을 암기하기 전에 어느 단계에서 생각이 달라졌는지 찾아보세요.

04·05·07·10편에는 별도 실행 가능한 Walkthrough 예제가 추가되어 있습니다. 기존 예제와 합쳐 21개 Java 실행 예제를 검증합니다. 예제 파일 전체를 복사해 실행하는 코드에는 `// file:` 이름을 표시했고, 본문 중 짧은 메서드·문장 조각은 기존 클래스 안에서 비교하는 연습임을 구분했습니다.

면접·심화·확인 문제를 합쳐 접었다 펼칠 수 있는 해설은 130개입니다. 가상 수치는 계산 원리를 보여 주는 예시이며 실측값과 구분합니다. GC 시점, JIT 결정, 스레드 실행 순서처럼 실행마다 달라질 수 있는 부분은 관찰 방법과 결론의 한계를 함께 읽으세요.
