ABOUT ME

안녕하세요, 백엔드 엔지니어 김동현입니다.

2018년부터 백엔드 개발을 해왔으며, 현재 컬리에서 물류 시스템을 개발하고 있습니다. 운영 복잡도가 높은 환경에서 반복적인 수작업을 자동화하고, 데이터 정합성과 서비스 안정성을 개선해 왔습니다.

반복되는 문제의 원인을 찾아 시스템 구조와 개발 방식을 함께 개선하는 일을 중요하게 생각합니다. 동시성 제어와 메시지 처리부터 테스트하기 좋은 도메인 설계, 안전한 기능 공개까지 실제 운영에서 필요한 답을 찾고 있습니다.

운영의 문제를 시스템의 개선으로

  • 수기 보정 작업 95% 이상 절감. 월 6,000~10,000건을 수기로 처리하던 입하 보정을 입고·재고 전반의 시스템 보정으로 전환했습니다. 분산 락과 Outbox 패턴을 적용해 동시 처리 충돌과 후속 메시지 유실 가능성에 대응했습니다.
  • 13개 물류센터의 회송·폐기 업무 연결. 하루 500~1,000건 규모의 업무를 5개 시스템으로 확장하는 과정에서 업무 프로세스와 DB·상태 전이 설계에 참여하고, 백엔드 API 개발을 전담했습니다.
  • 테스트 구조 개선과 운영 안정화. 비즈니스 로직을 도메인으로 옮기는 방식을 제안하고, 가이드와 세미나로 팀에 정착시켰습니다. 약 2년간 팀 전체에 5,000개 이상의 테스트가 축적되었고, 구조 개선과 테스트 확대를 이어가며 장애 빈도는 월 20건 이상에서 3~4개월에 한 번 수준으로 줄었습니다.
  • 배포와 기능 공개 분리. Flipt 기반 Feature Flag 도입과 운영 기준 정립을 주도했습니다. 오픈 일주일 전 운영 환경에 코드를 배포해 검증하고, 오픈일에는 플래그 전환으로 기능을 공개했습니다.

개발하는 방식도 함께 개선합니다

Swift 기반 멀티 에이전트 도구 Douglas와 여러 저장소의 코드 분석·개발 작업을 돕는 inbound-ai-suite를 단독으로 설계하고 개발했습니다. 반복되는 탐색과 작업을 줄여 팀이 문제 해결에 더 집중할 수 있는 도구를 만들고 있습니다.

테스트, CI/CD, DDD, Gradle 멀티 모듈, AWS, 개발 생산성을 주제로 15회 이상의 사내 기술 세미나를 진행했습니다. 직접 겪은 문제와 배운 내용을 나누며 팀과 함께 성장하는 것을 좋아합니다.

이곳에 기록하는 것

Java와 Spring, MySQL, Redis, Kafka를 중심으로 시스템이 동작하는 원리와 설계의 이유를 공부합니다. 복잡한 개념은 쉬운 비유로 풀고, 내부 원리와 운영에서의 고민까지 연결해 다시 찾아볼 수 있는 글을 남깁니다.
